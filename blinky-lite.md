<section class="section" id="security">
  <div class="container two-column">
    <div>
      <p class="eyebrow">Security architecture</p>

      <h2>Remote access, designed with security in mind.</h2>

      <p>
        Blinky-Lite uses publish-subscribe messaging. Devices initiate
        connections from inside the facility to a message broker,
        reducing the need for direct inbound access to edge devices.
      </p>

      <p>
        Role-based permissions help restrict access to applications and
        data. Appropriate network protection, authentication, secure
        configuration and ongoing operation remain essential.
      </p>

      <a class="text-link"
         href="https://blinky-lite.org/docs/pages/overview/security.html">
        Read the security overview →
      </a>
    </div>

    <div class="card">
      <h3>A layered approach</h3>

      <ul>
        <li>Devices initiate connections from inside the facility.</li>
        <li>Components communicate using publish-subscribe messaging.</li>
        <li>Role-based permissions help control access.</li>
        <li>Deployment and operating practices remain important.</li>
      </ul>
    </div>
